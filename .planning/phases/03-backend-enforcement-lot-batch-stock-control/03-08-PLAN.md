<interfaces>
Same fixture conventions as 03-07-PLAN.md (createTestUserWithRoles, Date.now()-suffixed unique
codes, cleanup in afterAll). Import order creation requires `IMPORT_COMPLIANCE_OFFICER` role per
the seeded permission matrix (`IMPORT_ORDER_CREATE` -> `["SYSTEM_ADMIN",
"IMPORT_COMPLIANCE_OFFICER"]`), status transitions to APPROVED/REJECTED go through the dedicated
approve/reject endpoints (blocked on generic PUT, same pattern as sales orders), but RECEIVED is a
plain status value settable via the generic `PUT /api/import-orders/:id`.

From `importOrder.controller.ts`'s `assertValidImportStatusTransition` (added by 03-05-PLAN.md):
known `status` vocabulary is `STAGING`, `PENDING_APPROVAL`, `APPROVED`, `CUSTOMS_CLEARED`,
`RECEIVED`, `ISSUE`, `REJECTED`. Pipeline order for `STAGING` -> `PENDING_APPROVAL` -> `APPROVED` ->
`CUSTOMS_CLEARED` -> `RECEIVED` -> `ISSUE` is forward-only; `REJECTED` and `ISSUE` are terminal — no
further `status` change is accepted once set.
</interfaces>
