<objective>
Build the single reusable audit-write utility (`AuditLogModel.record`) that every mutating
controller in this phase will call, and prove its two hardest properties on a small module before
replicating the pattern everywhere: (1) the audit write and the business mutation are atomic — one
`prisma.$transaction`, both commit or both roll back — and (2) `Decimal`/`Date` values inside
before/after snapshots serialize safely into the `Json` column. Also wire login/logout to emit
AUDIT-02 events, since auth.controller.ts's handlers are simple, standalone inserts (no `$transaction`
pairing needed) and are a natural, low-risk place to prove the "call `AuditLogModel.record` directly
against the singleton `prisma`, no tx" half of the utility's contract.

Purpose: AUDIT-01's atomicity guarantee is the single riskiest technical property in this phase
(RESEARCH.md Pitfall 2) — proving it once on Category before touching 10 more controllers avoids
repeating a subtle transaction-nesting bug 10 times.
Output: `lib/audit.ts`, audited category CRUD, audited login/logout, 3 passing test files.
</objective>

    ```typescript
    import type { PrismaClient, Prisma } from "@prisma/client";

    type Client = PrismaClient | Prisma.TransactionClient;

    export interface AuditRecordParams {
      entity: string;
      entityId: number | string;
      action: string; // "create" | "update" | "delete" | "login" | "logout" | "approve" | "reject" | "export"
      userId: number | null;
      before: unknown;
      after: unknown;
    }

    const jsonSafe = (value: unknown) => (value == null ? value : JSON.parse(JSON.stringify(value)));

    export const AuditLogModel = {
      record: (client: Client, params: AuditRecordParams) =>
        client.auditLog.create({
          data: {
            entity: params.entity,
            entityId: String(params.entityId),
            action: params.action,
            userId: params.userId,
            before: jsonSafe(params.before),
            after: jsonSafe(params.after),
          },
        }),
    };
    ```
    The `jsonSafe` helper round-trips every snapshot through `JSON.parse(JSON.stringify(value))`

    into plain strings, per RESEARCH.md Pitfall 4. `client` accepts either the singleton
    `PrismaClient` (for standalone calls like login/logout, Task 2) or a `Prisma.TransactionClient`
    (for controller-opened transactions) — both expose `.auditLog.create`.

    ```typescript
    import { prisma } from "../lib/prisma.js";
    import { AuditLogModel } from "../lib/audit.js";
    import type { AuthenticatedRequest } from "../middleware/auth.js";
    // ...existing imports...

    export const createCategory = asyncHandler(async (req: AuthenticatedRequest, res) => {
      const { categoryCode, categoryName, description, isActive } = req.body;
      if (!categoryCode || !categoryName) throw new HttpError(400, "categoryCode and categoryName are required");
      const category = await prisma.$transaction(async (tx) => {
        const created = await tx.category.create({ data: { categoryCode, categoryName, description, isActive } });
        await AuditLogModel.record(tx, { entity: "Category", entityId: created.categoryId, action: "create", userId: req.userId ?? null, before: null, after: created });
        return created;
      });
      res.status(201).json(category);
    });

    export const updateCategory = asyncHandler(async (req: AuthenticatedRequest, res) => {
      const { categoryCode, categoryName, description, isActive } = req.body;
      const category = await prisma.$transaction(async (tx) => {
        const before = await tx.category.findUnique({ where: { categoryId: Number(req.params.id) } });
        if (!before) throw new HttpError(404, "Category not found");
        const after = await tx.category.update({ where: { categoryId: Number(req.params.id) }, data: { categoryCode, categoryName, description, isActive } });
        await AuditLogModel.record(tx, { entity: "Category", entityId: after.categoryId, action: "update", userId: req.userId ?? null, before, after });
        return after;
      });
      res.json(category);
    });

    export const deleteCategory = asyncHandler(async (req: AuthenticatedRequest, res) => {
      await prisma.$transaction(async (tx) => {
        const before = await tx.category.findUnique({ where: { categoryId: Number(req.params.id) } });
        if (!before) throw new HttpError(404, "Category not found");
        await tx.category.delete({ where: { categoryId: Number(req.params.id) } });
        await AuditLogModel.record(tx, { entity: "Category", entityId: before.categoryId, action: "delete", userId: req.userId ?? null, before, after: null });
      });
      res.status(204).end();
    });
    ```
    This exact shape (find-before, mutate, record-after, all inside one `tx`) is the template every
    later write-wave plan in this phase (02-08, 02-09, 02-10) replicates for its own modules.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| controller -> AuditLog table | The audit trail is the accountability record for AUDIT-01/02; if writes here are not atomic with the mutation, the trail becomes unreliable exactly when it matters most (a failure mid-operation) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Repudiation | Audit write silently skipped or non-atomic with its mutation | mitigate | Both writes happen inside one `prisma.$transaction`; `audit.atomicity.test.ts` directly proves a failed mutation leaves zero AuditLog rows too |
| T-02-08 | Tampering | Malformed `Decimal`/`Date` values corrupting the stored JSON snapshot | mitigate | `jsonSafe()` normalizes every snapshot through `JSON.parse(JSON.stringify(...))` before it reaches the `Json` column, per RESEARCH.md Pitfall 4 |
| T-02-09 | Repudiation | Login/logout audit events missing because the user session was already invalid | accept | If no valid session exists there is no authenticated identity to attribute the audit event to; this is a correct "nothing to log" case, not a gap — `requireAuth` already rejects logout attempts with no valid token before this code path is reached |
</threat_model>
