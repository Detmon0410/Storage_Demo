<objective>
Refactor the four models that already open their own internal `prisma.$transaction` calls
(`ImportOrderModel`, `SalesOrderModel`, `StockTransactionModel`, `CustomerLicenseModel.renew`) so
each accepts an optional external `client: PrismaClient | Prisma.TransactionClient`. Without this,
a controller in plan 02-10 (import/sales order write+audit wrap) that opens its own
`prisma.$transaction` and then calls e.g. `ImportOrderModel.create()` would trigger that model's
*internal* `prisma.$transaction`, which Prisma cannot nest — producing two independent transactions
instead of one atomic unit, silently breaking AUDIT-01's atomicity guarantee (RESEARCH.md Pitfall 2).

Purpose: this is pure plumbing refactor work, isolated to the model layer, so it can land now
(Wave 2, parallel to plans 02-02/02-03) without waiting on or blocking the audit/permission
infrastructure — but it must complete before plan 02-10 (which calls these models from inside a
controller-opened transaction).
Output: 4 refactored model files, unchanged external behavior, one new regression test file.
</objective>

```typescript
import type { PrismaClient, Prisma } from "@prisma/client";

create: (data: { /* ...existing fields...; */ createdById?: number }, client: Client = prisma) => {
  const rows = toItemRows(data.items);
  const run = async (tx: Client) => {
    const order = await tx.importOrder.create({ data: { /* ...existing fields..., */ createdById: data.createdById }, include: withRelations });
    await createStockInTx(tx as Prisma.TransactionClient, data.orderNo, data.items);
    return order;
  };
  return "$transaction" in client ? client.$transaction((tx) => run(tx)) : run(client);
},
```
The `"$transaction" in client` check distinguishes the singleton `PrismaClient` (which has
`.$transaction`) from an already-open `Prisma.TransactionClient` (which does not) — when a tx is
passed in, run directly on it (join the caller's transaction); when the plain singleton is passed
(or nothing, via the default), open a new transaction as before (preserves today's standalone
behavior for `seed.ts` and any other non-audited call site).

Current `apps/backend/src/models/importOrder.model.ts` (full file, for exact before/after diffing —
already read in full during planning, reproduced here so this task doesn't need to re-read it):
lines 40-142 define `ImportOrderModel.create/update/delete`, each currently calling
`prisma.$transaction(async (tx) => {...})` directly. Apply the same transformation to all three
methods. `SalesOrderModel` (apps/backend/src/models/salesOrder.model.ts) is structurally identical
— same transformation, same `Client` type alias.

`StockTransactionModel.create`/`delete` (apps/backend/src/models/stockTransaction.model.ts) already
have tx-first internal helpers (`createStockTransactionTx`, `reverseAndDeleteByReferenceTx`) — only
the two top-level exports need the optional-client wrapper:
```typescript
create: (data: StockTransactionInput, client: Client = prisma) =>
  "$transaction" in client ? client.$transaction((tx) => createStockTransactionTx(tx, data)) : createStockTransactionTx(client, data),
delete: (transactionId: number, client: Client = prisma) => {
  const run = async (tx: Client) => {
    const transaction = await tx.stockTransaction.delete({ where: { transactionId } });
    await tx.product.update({ where: { productId: transaction.productId }, data: { stockQty: { increment: -stockDelta(transaction.transactionType, transaction.quantity) } } });
    return transaction;
  };
  return "$transaction" in client ? client.$transaction((tx) => run(tx)) : run(client);
},
```

`CustomerLicenseModel.renew` (apps/backend/src/models/customerLicense.model.ts) is the only method
on that model with an internal `$transaction` — apply the identical optional-client wrapper to just
`renew`; leave `create`/`update`/`delete`/`findAll`/`findById` untouched (they have no internal
transaction to conflict with, so controllers can call `tx.customerLicense.create/update/delete`
directly in plan 02-08, matching the Category pattern from plan 02-03).
