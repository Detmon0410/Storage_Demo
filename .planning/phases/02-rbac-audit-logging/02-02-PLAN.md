<objective>
Build the `requirePermission(code)` middleware — the single enforcement mechanism RBAC-04 requires
on every mutating endpoint — backed by a reusable `role.model.ts` permission-union query that is
re-derived from the database on every request (RBAC-06: no caching, no JWT-embedded permissions).

module — no internal transactions, no special business rules) before this pattern is replicated
across the other 10 route files in later plans.

on. Building and proving it once on a small, low-risk module avoids repeating design mistakes across
11 route files.

```typescript
import type { NextFunction, Request, Response } from "express";
import { HttpError } from "./errorHandler.js";
import { verifyAccessToken } from "../lib/jwt.js";

export interface AuthenticatedRequest extends Request {
  userId?: number;
}

export function requireAuth(req: AuthenticatedRequest, _res: Response, next: NextFunction) {
  const header = req.headers.authorization;
  const token = header?.startsWith("Bearer ") ? header.slice(7) : undefined;
  if (!token) return next(new HttpError(401, "Not authenticated"));
  try {
    const payload = verifyAccessToken(token);
    req.userId = payload.userId;
    next();
  } catch {
    next(new HttpError(401, "Invalid or expired session"));
  }
}
```

       ```typescript
       import { prisma } from "../lib/prisma.js";

       export const RoleModel = {
         getUserPermissionCodes: async (userId: number): Promise<Set<string>> => {
           const user = await prisma.user.findUnique({
             where: { id: userId },
             include: {
               userRoles: {
                 include: { role: { include: { rolePermissions: { include: { permission: true } } } } },
               },
             },
           });
           const codes = new Set<string>();
           for (const ur of user?.userRoles ?? []) {

               codes.add(rp.permission.permissionCode);
             }
           }
           return codes;
         },
         getUserRoleCodes: async (userId: number): Promise<string[]> => {
           const user = await prisma.user.findUnique({
             where: { id: userId },
             include: { userRoles: { include: { role: true } } },
           });
           return (user?.userRoles ?? []).map((ur) => ur.role.roleCode);
         },
       };
       ```

    2. Create `apps/backend/src/middleware/permission.ts` mirroring `auth.ts`'s exact conventions
       (interface-extension pattern, `HttpError` + `next(new HttpError(...))`, `.js` import
       extensions, plain exported function):
       ```typescript
       import type { NextFunction, Response } from "express";
       import { HttpError } from "./errorHandler.js";
       import { RoleModel } from "../models/role.model.js";
       import type { AuthenticatedRequest } from "./auth.js";

       export interface PermissionRequest extends AuthenticatedRequest {
         permissions?: Set<string>;
       }

       export function requirePermission(code: string) {
         return async (req: PermissionRequest, _res: Response, next: NextFunction) => {
           if (!req.userId) return next(new HttpError(401, "Not authenticated"));
           try {
             req.permissions ??= await RoleModel.getUserPermissionCodes(req.userId);
             if (!req.permissions.has(code)) {
               return next(new HttpError(403, "Insufficient permissions"));
             }
             next();
           } catch (err) {
             next(err);
           }
         };
       }
       ```
       `req.permissions ??= ...` is per-request memoization only (not a cross-request cache) — if a
       single request chain has two `requirePermission` calls, the second reuses the same request's
       already-fetched set rather than re-querying. This does not violate RBAC-06 since nothing
       survives past the current request.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Elevation of Privilege | `requirePermission` middleware | mitigate | Permission set is always freshly queried from `RoleModel.getUserPermissionCodes` per request; never trusts a client-supplied role/permission claim (no such claim is ever read from `req.body`/`req.query`) |
| T-02-05 | Elevation of Privilege | Stale-permission exploitation via an old access token after role revocation | mitigate | RBAC-06 requires DB re-derivation per request — proven directly by `rbac.revocation.test.ts`'s same-token-before/after-role-change assertions |
| T-02-06 | Information Disclosure | Permission-denial responses leaking which permission code was required | accept | `HttpError(403, "Insufficient permissions")` is a generic message with no code disclosure; low-severity even if the code were disclosed since permission codes are not secrets |
