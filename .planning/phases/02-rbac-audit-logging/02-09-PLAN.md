Product and InventoryStock follow the exact `tx.<entity>.create/update/delete` direct-call pattern
from plan 02-03's Category controller (both models are plain single-call with no internal
transaction — confirmed during planning by reading `product.model.ts`/`inventoryStock.model.ts` in
full).

StockTransaction's controller must call the model, not `tx.stockTransaction.create` directly,
because `StockTransactionModel.create`/`.delete` (refactored in plan 02-04) also perform the
`product.stockQty` increment/decrement as part of the same logical write:
```typescript
// apps/backend/src/controllers/stockTransaction.controller.ts — target shape
export const createStockTransaction = asyncHandler(async (req: AuthenticatedRequest, res) => {
  // ...existing body parsing/validation...
  const transaction = await prisma.$transaction(async (tx) => {
    const created = await StockTransactionModel.create({ transactionNo, productId, transactionType, quantity, transactionDate, referenceNo, note }, tx);
    await AuditLogModel.record(tx, { entity: "StockTransaction", entityId: created.transactionId, action: "create", userId: req.userId ?? null, before: null, after: created });
    return created;
  });
  res.status(201).json(transaction);
});
```
Note `StockTransactionModel.create(data, tx)` (plan 02-04's signature) internally checks
`"$transaction" in client` — since `tx` is already a `Prisma.TransactionClient` (no `$transaction`
method), it runs directly on `tx` rather than opening a nested transaction, joining the controller's
outer transaction correctly.
