<objective>
Apply the audit-wrap + write-permission pattern proven in plan 02-03 (Category) to the 5 modules
whose GET routes were already permission-gated in plan 02-05: `customer`, `customerLicense`,
`dashboardKpi`, `license`, `supplier`. For 4 of these (customer, dashboardKpi, license, supplier),
the model layer does plain single-call `prisma.x.create/update/delete()` with no business logic
worth preserving in a separate layer — the controller opens `prisma.$transaction` and calls
`tx.x.create/update/delete()` directly, exactly mirroring plan 02-03's Category pattern. For
`customerLicense`, the model layer has real business logic (actor tracking, status-change
timestamps, the `renew()` transaction) that must be preserved — so this plan extends plan 02-04's
already-added `Client` type alias on `CustomerLicenseModel` to `create`/`update` too, letting the
controller pass its own `tx` through instead of bypassing the model.

Purpose: RBAC-04 (write-permission enforcement) and AUDIT-01 (atomic create/update/delete logging)
for 5 of the 10 remaining business modules — the other 5 are handled in plans 02-09/02-10.
Output: 5 controllers with audited, permission-gated mutations; 5 route files with full CRUD
permission wiring; 2 new test files.
</objective>

<!-- Reference pattern from plan 02-03's category.controller.ts (already built) -->
```typescript
export const createSupplier = asyncHandler(async (req: AuthenticatedRequest, res) => {
  const { supplierCode, supplierName, country, contactName, email, phone, status } = req.body;
  if (!supplierCode || !supplierName) throw new HttpError(400, "supplierCode and supplierName are required");
  const supplier = await prisma.$transaction(async (tx) => {
    const created = await tx.supplier.create({ data: { supplierCode, supplierName, country, contactName, email, phone, status } });
    await AuditLogModel.record(tx, { entity: "Supplier", entityId: created.supplierId, action: "create", userId: req.userId ?? null, before: null, after: created });
    return created;
  });
  res.status(201).json(supplier);
});
```
