```prisma
enum UserStatus {
  ACTIVE
  INACTIVE
}

model User {
  id            Int            @id @default(autoincrement()) @map("user_id")
  username      String         @unique
  passwordHash  String         @map("password_hash")
  status        UserStatus     @default(ACTIVE)
  createdAt     DateTime       @default(now()) @map("created_at")
  refreshTokens RefreshToken[]

  @@map("users")
}

model RefreshToken {
  id        Int       @id @default(autoincrement()) @map("refresh_token_id")
  tokenHash String    @unique @map("token_hash")
  userId    Int       @map("user_id")
  expiresAt DateTime  @map("expires_at")
  revokedAt DateTime? @map("revoked_at")
  createdAt DateTime  @default(now()) @map("created_at")

  user User @relation(fields: [userId], references: [id])

  @@map("refresh_tokens")
}
```

```typescript
const adminUsername = "admin";
const adminPassword = process.env.ADMIN_DEFAULT_PASSWORD ?? "changeme123";
const existingAdmin = await prisma.user.findUnique({ where: { username: adminUsername } });
if (!existingAdmin) {
  const passwordHash = await argon2.hash(adminPassword);
  await prisma.user.create({
    data: { username: adminUsername, passwordHash, status: "ACTIVE" },
  });
  console.log(`Seeded default System Admin user "${adminUsername}" (password: ${adminPassword} — change in production via ADMIN_DEFAULT_PASSWORD env var)`);
} else {
  console.log(`System Admin user "${adminUsername}" already exists, skipping`);
}
```

This must be idempotent (checked via `findUnique` before `create`) so `pnpm --filter backend run db:setup` never fails or duplicates the admin account on repeat runs — matches how the rest of this seed file relies on `db push` giving a fresh schema, but this specific block is defensive since `db:setup` can be re-run against a non-empty DB during development.

|-----------|----------|-----------|-------------|-----------------|

| T-01-02 | Tampering | `passwordHash` column at rest | accept | Column stores only the Argon2id hash, not raw password; a DB leak alone does not expose credentials. Full column encryption is out of scope — hashing is the standard ASVS V6 control here |
