# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled Tailwind v4 component set already established in `apps/frontend/src/components/ui/`) |
| Preset | not applicable |
| Component library | none (custom components: `Button`, `Field`/`TextInput`, `Card`, `States`, `Modal`, `Toast`, etc.) |
| Icon library | `lucide-react` (already a dependency, used throughout — e.g. `AlertTriangle`, `Inbox`, `RefreshCw`, `Menu`) |
| Font | `"Segoe UI", "Noto Sans Thai", system-ui, -apple-system, sans-serif` (defined as `--font-sans` in `apps/frontend/src/index.css`) |

**Decision rationale:** No `components.json`/shadcn exists in this repo. The frontend already has 20+ pages built on a consistent, mature hand-rolled Tailwind design system (slate neutrals, amber-600 accent, rose destructive, `rounded-lg`/`rounded-xl`, `Card`, `Button`, `Field` primitives). Introducing shadcn for a single login page would fragment the existing visual language rather than extend it. This phase's Login/Logout UI **reuses the existing primitives** — `Card`, `Button`, `TextInput`, `Field` — rather than inventing new ones. Per the shadcn gate, this is a reasonable-default proceed-without-asking call: the project already answered "what design system" with its existing codebase before this phase began.

## Spacing Scale

Declared values (must be multiples of 4), matching existing Tailwind usage across the codebase (`px-3.5 py-2`, `gap-3`, `mb-6`, `py-16`, etc.):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (e.g. `gap-1.5` button icon spacing) |
| sm | 8px | Compact element spacing (form label-to-input gap) |
| md | 16px | Default element spacing (`gap-4` form grid, `py-3` topbar) |
| lg | 24px | Section padding (`mb-6` page header, login card internal padding) |
| xl | 32px | Layout gaps (space between login card and page edge on desktop) |
| 2xl | 48px | Major section breaks (vertical centering padding on login screen) |
| 3xl | 64px | Page-level spacing (not used in this phase — single-card login layout) |

Exceptions: Login/logout screens have no data tables or dashboards, so `2xl`/`3xl` tokens apply only to the vertical centering of the single login `Card` on the page, not to multi-section layouts.

## Typography

Matches existing scale observed in `PageHeader.tsx`, `Field.tsx`, `Topbar.tsx` — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Heading | 20px (`text-xl`) | 600 (semibold) | 1.2 |
| Display | 24px (`text-2xl`) | 600 (semibold) | 1.2 — used only for the login screen's app name/title above the form, matching `app.name` branding weight |

Exactly 4 sizes / 2 weights: 400 (regular, used for Body and Label) and 600 (semibold, used for Heading and Display). No other weight values are used anywhere in this phase's UI — `font-medium` (500) is not used on the login/logout screens.

## Color

Matches existing Tailwind palette usage (slate neutrals, amber accent, rose destructive) — no new colors introduced for this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `slate-50` (#f8fafc) background / `white` (#ffffff) card surface | Page background (`body` already sets `bg-slate-50`), login card background |
| Secondary (30%) | `slate-200`/`slate-300` (#e2e8f0 / #cbd5e1) | Card border (`border-slate-200`), input border (`border-slate-300`), dividers |
| Accent (10%) | `amber-600` (#d97706) | Primary "Log in" button, focus ring on username/password inputs, link/text emphasis (e.g. "forgot password" if present), user-avatar badge in Topbar (post-login) |
| Destructive | `rose-600` (#e11d48) / `rose-500` for text | Login error message text/border only (invalid credentials, rate-limit exceeded), logout confirmation if a confirm step is added |

Accent reserved for: the primary "Log in" submit button, input focus rings on the login form, and the post-login user-avatar badge in `Topbar`. Never used for body text, borders, or secondary actions.

**Visual anchor:** On the login screen, the `Card` containing the form plus the primary amber "Log in" button is the focal point — the app name/heading above the card is secondary, providing context but not competing for attention (smaller visual weight via spacing, not color).

## Copywriting Contract

Copy is delivered via `i18next` (`apps/frontend/src/i18n/locales/en.ts` / `ja.ts`), matching the existing `common.*` / `app.*` key structure. New keys to add under an `auth.*` namespace:

| Element | Copy |
|---------|------|
| Primary CTA | "Log in" (`auth.loginButton`) — button shows a spinner + disabled state while the request is in flight, matching existing `Button` `loading` prop pattern |
| Page heading | "Sign in to {{appName}}" (`auth.heading`) — reuses `app.name` ("Liquor Import & Distribution") |
| Username field label | "Username" (`auth.usernameLabel`) — per D-06, no email field |
| Password field label | "Password" (`auth.passwordLabel`) |
| Empty state heading | Not applicable — login form has no empty/list state |
| Error state (invalid credentials) | "Incorrect username or password. Please try again." (`auth.invalidCredentials`) — deliberately does not reveal which field was wrong, per research Pitfall/ASVS V2 guidance |
| Error state (rate limited) | "Too many login attempts. Please wait a few minutes and try again." (`auth.rateLimited`) — maps to backend 429 `express-rate-limit` message |
| Error state (network/server) | Reuse existing `common.connectionError` pattern: "Could not connect to the server. Please check that the backend is running." |
| Session expired (silent-refresh failure) | "Your session has expired. Please log in again." (`auth.sessionExpired`) — shown on redirect to `/login` when `/api/auth/refresh` returns 401 |
| Logout action | "Log out" (`auth.logoutButton`) — placed in `Topbar` user menu, replacing/extending the current static `U` avatar + `app.user` label |
| Destructive confirmation | Logout: no confirmation dialog required (logout is low-risk/reversible via re-login) — do not add a `ConfirmDialog` for this action, keep it a single click per existing UX weight for non-destructive actions |

## Interaction & State Notes (phase-specific)

Not part of the template's core sections but required for executor clarity given AUTH-01..07:

- **Login form states:** idle → submitting (button `loading`, inputs disabled) → success (redirect to `/`) / error (inline error banner above form using `ErrorState`-style rose text, form remains filled except password field is NOT cleared per usability, only re-focused).
- **Route guard:** Unauthenticated access to any existing route redirects to `/login`; after successful login, redirect back to the originally requested route (or `/` if none).
- **Silent refresh on mount:** App shows existing `LoadingState` component (already built, reused as-is) while `AuthProvider` resolves `/api/auth/refresh` on initial load — no new loading UI needed.
- **Logout entry point:** Add to the existing user badge area in `Topbar.tsx` (currently a static `U` avatar + `app.user` text) — convert to a small dropdown/menu with the logout action, styled consistently with existing `ghost` button variant.
