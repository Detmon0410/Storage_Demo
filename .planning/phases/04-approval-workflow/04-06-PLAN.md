<objective>
Bring the two order-management pages back in sync with the Phase 4 backend field split: remove the
now-nonfunctional free-text `approver` inputs (approval is server-side and automatic per D-04/D-05 —
there is no "type an approver name to bypass a warning" flow anymore), rename the Import Orders
page's status field/filter to the new `logisticsStatus`, and surface the real approval `status`
(including `REJECTED` with its `rejectionReason`) as a read-only display on both tables. This phase
is backend-first per CONTEXT.md — no new screens, only field-name/display corrections so the existing
UI compiles and accurately reflects the new backend behavior.

Purpose: `SalesOrdersPage.tsx`'s client-side `needsApproval` gate currently blocks form submission
based on a free-text `approver` field the user types into — this duplicated, now-obsolete
client-side logic must be removed since the backend auto-routes to PENDING_APPROVAL regardless of
what the client sends. `ImportOrdersPage.tsx`'s `status` field/filter must follow the backend rename
or the page will send an invalid/rejected field to the API.
Output: Updated types.ts, both order pages, status.ts tone mapping, and both locale files.
</objective>
