<objective>
Rewire both order models so the real `status` enum (not the interim `requiresApproval` boolean, not
the overloaded `ImportOrder.status` string) drives when stock is decremented/received. This is the
highest-risk regression point in the phase: the import-order RECEIVED-gated stock-in logic must
require BOTH the renamed `logisticsStatus === "RECEIVED"` AND the new `status === "APPROVED"` —
gating on only one re-introduces an approval-bypass bug (flagged in STATE.md, RESEARCH.md Pitfall/
Anti-Pattern, and this phase's critical_regression_risk note).

Purpose: APPROVAL-02/03 require stock to have zero effect until an order is APPROVED, and to
decrement exactly at that transition. APPROVAL-05 requires the import-order value threshold to
auto-route to PENDING_APPROVAL, mirroring the existing sales-order credit/discount pattern.
Output: Updated salesOrder.model.ts and importOrder.model.ts, both compiling against the Phase 4
schema from 04-01.
</objective>
